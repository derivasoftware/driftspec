see-design draws every diagram of a workspace (DS-474). It draws the svg and text drawings through render, describes the render-IR, and writes the viewer's page framed on a diagram. It also says, when asked whole, which diagrams did not read whole (DS-433). So `ds render`, the engine's render and page, and the Python face no longer draw anything themselves; their output is byte for byte what it was. A drawing reaches the sink lent to see-design as one verbatim text, which a sink of emit now accepts once per document. The text sink writes it as it is, the JSON sink fails NotImplemented, and the Python sink keeps it as a str, so `Workspace.run("see-design", {"format": "svg", ...})` returns the drawing. This is a bridge until a figure is described as marks (DS-463). FormatFactory keeps only the viewer's page: the svg and text writers (DiagramSvg, DiagramText) are gone, and so are the drawing options of FormatOptions (pretty, width, color). The table of questions `ds query` answers now lives in the manual, and both the query and the command line's help read it there. Two rules hold the doors in the design. One is that the command line and the api know no model: the loading machinery (Workspace, Api, Bound) is exempted for good, and the playground's Browser until DS-460. The other is that the command line reaches the engine only through the workspace.
